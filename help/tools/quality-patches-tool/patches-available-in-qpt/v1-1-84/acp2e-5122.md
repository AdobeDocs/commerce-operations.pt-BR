# ACP2E-5122: Erros de carrinho tratados do GraphQL são gravados incorretamente no log de exceções

O patch ACP2E-5122 corrige o problema em que os erros de solicitação do carrinho do GraphQL manipulados são gravados no log de exceções como erros de aplicativo. Este patch está disponível quando o [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84 está instalado. A ID do patch é ACP2E-5122. Observe que esse problema está programado para ser corrigido no Adobe Commerce 2.4.10.

## Produtos e versões afetados

**O patch foi criado para a versão do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) 2.4.8-p5

**Compatível com as versões do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) 2.4.4 - 2.4.9

>[!NOTE]
>
>O patch pode se tornar aplicável a outras versões com as novas versões do [!DNL Quality Patches Tool]. Para verificar se o patch é compatível com a sua versão do Adobe Commerce, atualize o pacote `magento/quality-patches` para a versão mais recente e verifique a compatibilidade na [[!DNL Quality Patches Tool]: página Procurar patches](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use a ID do patch como palavra-chave de pesquisa para localizar o patch.

## Problema

Os erros de solicitação de carrinho do GraphQL tratados são gravados no log de exceções como erros de aplicativo.

<u>Etapas a serem reproduzidas</u>:

1. Envie uma mutação do GraphQL `placeOrder` com uma ID de carrinho mascarado inválida, expirada ou já destruída, como esta mutação:

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. Verifique a resposta do GraphQL.
1. Verifique `var/log/exception.log` para ver se há erros no carrinho.

<u>Resultados esperados</u>:

1. A solicitação GraphQL retorna uma carga de erro tratada voltada para o cliente para o carrinho inválido sem uma resposta *HTTP 500*.
1. A *GraphQlNosuchEntityException* manipulada não é gravada em `var/log/exception.log` e, em vez disso, é roteada para um canal de log de severidade mais baixa.

<u>Resultados reais</u>:

Cada solicitação grava a exceção tratada em `var/log/exception.log` com a severidade `report.ERROR`, o que causa um aumento de log ilimitado durante solicitações repetidas.
