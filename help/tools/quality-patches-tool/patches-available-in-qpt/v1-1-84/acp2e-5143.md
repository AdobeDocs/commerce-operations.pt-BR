# ACP2E-5143: a consulta do GraphQL `route` renderiza conteúdo de página do CMS não solicitado

O patch ACP2E-5143 corrige o problema em que a consulta do GraphQL `route` renderiza o conteúdo completo da página do CMS, incluindo widgets do Page Builder e listas de produtos, mesmo quando apenas campos de roteamento de URL são solicitados, o que atrasa a resolução do URL. Este patch está disponível quando o [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84 está instalado. A ID do patch é ACP2E-5143. Observe que esse problema está programado para ser corrigido no Adobe Commerce 2.4.10.

## Produtos e versões afetados

**O patch foi criado para a versão do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) 2.4.7-p9

**Compatível com as versões do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) 2.4.4 - 2.4.7-p10

>[!NOTE]
>
>O patch pode se tornar aplicável a outras versões com as novas versões do [!DNL Quality Patches Tool]. Para verificar se o patch é compatível com a sua versão do Adobe Commerce, atualize o pacote `magento/quality-patches` para a versão mais recente e verifique a compatibilidade na [[!DNL Quality Patches Tool]: página Procurar patches](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use a ID do patch como palavra-chave de pesquisa para localizar o patch.

## Problema

Problema em que a consulta `route` do GraphQL renderiza o conteúdo completo da página do CMS, incluindo widgets do Page Builder e listas de produtos, mesmo quando apenas campos de roteamento de URL são solicitados, o que torna a resolução do URL mais lenta.

<u>Pré-requisitos</u>:

O Page Builder está instalado.

<u>Etapas a serem reproduzidas</u>:

1. Vá para Admin > **[!UICONTROL Content]** > **[!UICONTROL Elements]** > **[!UICONTROL Pages]** e clique em **[!UICONTROL Add New Page]**.
1. Insira os detalhes da página, defina **[!UICONTROL Enable Page]** como **[!UICONTROL Yes]** e clique em **[!UICONTROL Edit with Page Builder]** na seção **[!UICONTROL Content]**. Expanda **[!UICONTROL Add Content]** no painel do Page Builder e arraste para o palco um espaço reservado de **[!UICONTROL Products]**, ou insira um widget de produto de catálogo no conteúdo da página.
1. No Admin, vá para **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL Configuration]**. No painel esquerdo, em **[!UICONTROL General]**, escolha **[!UICONTROL Web]** e expanda **[!UICONTROL Default Pages]**. Defina **[!UICONTROL CMS Home Page]** para a nova página e clique em **[!UICONTROL Save Config]**.
1. Envie a seguinte solicitação do GraphQL:

   ```
   query ResolveURL($url: String!) {
     route(url: $url) {
       relative_url
       redirect_code
       type
       ... on CmsPage { identifier __typename }
       ... on ProductInterface { uid __typename }
       ... on CategoryInterface { uid __typename }
       __typename
     }
   }
   ```

1. Use as seguintes variáveis para a solicitação:

   ```
   { "url": "/" }
   ```

<u>Resultados esperados</u>:

A consulta `route` retorna os metadados de roteamento solicitados e os campos discriminadores de tipo para a página inicial do CMS sem renderizar seu conteúdo completo.

<u>Resultados reais</u>:

1. A consulta `route` renderiza o conteúdo completo da página inicial do CMS, mesmo que apenas os metadados de roteamento e campos discriminadores de tipo sejam solicitados.
1. Os widgets do Page Builder carregam coleções de produtos, aumentando o tempo de resposta e o número de consultas ao banco de dados por solicitação.
