# AC-18096: Os campos de data do Sales GraphQL retornam um formato localizado incorreto

O patch AC-18096 corrige o problema em que os campos de data do Sales GraphQL retornam datas em um formato diferente dos lançamentos anteriores, revertendo o formato de data de `/` separado por barra para `-` separado por traço. Este patch está disponível quando o [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 está instalado. A ID do patch é AC-18096. Observe que esse problema foi corrigido no Adobe Commerce 2.4.9.

## Produtos e versões afetados

**O patch foi criado para a versão do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) 2.4.9

**Compatível com as versões do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) >2.4.8 &lt;=2.4.9-p1

>[!NOTE]
>
>O patch pode se tornar aplicável a outras versões com as novas versões do [!DNL Quality Patches Tool]. Para verificar se o patch é compatível com a sua versão do Adobe Commerce, atualize o pacote `magento/quality-patches` para a versão mais recente e verifique a compatibilidade na [[!DNL Quality Patches Tool]: página Procurar patches](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=pt-BR). Use a ID do patch como palavra-chave de pesquisa para localizar o patch.

## Problema

Os campos de data do Sales GraphQL retornam valores de data e hora no formato separado por barra `(d/m/Y H:i:s)` em vez do formato separado por traço `(Y-m-d H:i:s)` usado no Adobe Commerce 2.4.8

<u>Pré-requisitos</u>:

- **[!UICONTROL General]** > **[!UICONTROL Locale Options]** > **[!UICONTROL Timezone]**: *Europa/Paris*
- **[!UICONTROL General]** > **[!UICONTROL Locale Options]** > **[!UICONTROL Locale]**: *Francês (França)*

<u>Etapas a serem reproduzidas</u>:

1. Criar um pedido.
1. Recuperar detalhes da data do pedido usando o GraphQL:

   ```graphql
   query getOrders {
       customer {
           orders {
               items {
                   orderDateOK: created_at
                   orderDateFAIL: order_date
               }
           }
       }
   }
   ```

<u>Resultados esperados</u>:

- Os campos retornam valores em `Y-m-d H:i:s`, correspondendo à saída na versão 2.4.8.

<u>Resultados reais</u>:

- Os campos retornam valores em `d/m/Y H:i:s`, como `27/08/2026 14:12:55`, em vez de `Y-m-d H:i:s`, como `2026-08-27 14:12:55`.
