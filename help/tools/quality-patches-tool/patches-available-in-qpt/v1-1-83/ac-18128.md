# AC-18128: as datas de pedido do GraphQL e os carimbos de data e hora de comentário estão incorretos para locais que não sejam em inglês

O patch AC-18128 corrige o problema em que as datas de pedido e os carimbos de data e hora do comentário do pedido retornados pelo GraphQL podem exibir datas do calendário incorretas em configurações de local em outros idiomas. Este patch está disponível quando o [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 está instalado. A ID do patch é AC-18128. Observe que esse problema foi corrigido no Adobe Commerce 2.4.8.

## Produtos e versões afetados

**O patch foi criado para a versão do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) 2.4.8

**Compatível com as versões do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) >=2.4.8 &lt;2.4.8-p6

>[!NOTE]
>
>O patch pode se tornar aplicável a outras versões com as novas versões do [!DNL Quality Patches Tool]. Para verificar se o patch é compatível com a sua versão do Adobe Commerce, atualize o pacote `magento/quality-patches` para a versão mais recente e verifique a compatibilidade na [[!DNL Quality Patches Tool]: página Procurar patches](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Use a ID do patch como palavra-chave de pesquisa para localizar o patch.

## Problema

As datas do pedido e os carimbos de data e hora do comentário do pedido retornados pelo GraphQL podem exibir datas do calendário incorretas em configurações de local que não estejam em inglês.

<u>Etapas a serem reproduzidas</u>:

1. No painel Admin, vá para **[!UICONTROL Stores]** > **[!UICONTROL Configuration]** > **[!UICONTROL General]** > **[!UICONTROL Locale Options]**. Defina **[!UICONTROL Timezone]** como *Europa/Paris*. Defina **[!UICONTROL Locale]** como *Francês (França)*. Salve a configuração.
1. Faça um pedido na vitrine.
1. Execute a seguinte consulta GraphQL de Ordens do Cliente:

   ```graphql
   query getOrders {
       customer {
           orders {
               items {
                   orderDateOK: created_at
                   orderDateFAIL: order_date
               }
           }
       }
   }
   ```

<u>Resultados esperados</u>:

Os carimbos de data e hora do pedido e de comentário nas respostas do GraphQL refletem a data correta do calendário, independentemente da localidade da loja.

<u>Resultados reais</u>:

Para localidades diferentes de `en_US`, como `fr_FR` e `de_DE`, `order_date` mostra a data de calendário errada devido a um problema de análise de data.
