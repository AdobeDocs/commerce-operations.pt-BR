# ACP2E-4799: a consulta GraphQL `requisition_lists` retorna `total_count` incorreto com paginação

O patch ACP2E-4799 corrige o problema em que a consulta do GraphQL `requisition_lists` retorna um valor de `total_count` incorreto que reflete somente o número de itens na página atual em vez do número total de entidades de lista de requisições correspondentes aos critérios de consulta. Este patch está disponível quando o [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82 está instalado. A ID do patch é ACP2E-4799. Observe que este problema está programado para ser corrigido no Adobe Commerce B2B 1.5.4.

## Produtos e versões afetados

**O patch foi criado para a versão do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) B2B 1.5.2-p4

**Compatível com as versões do Adobe Commerce:**

* Adobe Commerce (todos os métodos de implantação) B2B >=1.5.0 &lt;1.5.3

>[!NOTE]
>
>O patch pode se tornar aplicável a outras versões com as novas versões do [!DNL Quality Patches Tool]. Para verificar se o patch é compatível com a sua versão do Adobe Commerce, atualize o pacote `magento/quality-patches` para a versão mais recente e verifique a compatibilidade na [[!DNL Quality Patches Tool]: página Procurar patches](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=pt-BR). Use a ID do patch como palavra-chave de pesquisa para localizar o patch.

## Problema

Quando os clientes consultam listas de requisições com paginação, o campo `total_count` não reflete o número completo de listas de requisições correspondentes. Em vez disso, ele relata apenas o número de itens retornados para a página atual, o que torna os metadados de paginação imprecisos.

<u>Pré-requisitos</u>:

As listas de requisição estão ativadas para o Adobe Commerce B2B.

<u>Etapas a serem reproduzidas</u>:

1. No Admin, vá para **[!UICONTROL Stores]** > **Configurações** > **Configuração**.
1. No painel esquerdo, em **Geral**, escolha **Recursos B2B**.
1. Defina **[!UICONTROL Enable Requisition List]** como **[!UICONTROL Yes]** e selecione **[!UICONTROL Save Config]**.
1. Faça logon na loja como cliente.
1. Escolha **[!UICONTROL My Requisition Lists]** e crie seis listas de requisições.
1. Certifique-se de que o cliente tenha exatamente seis listas de requisições e que cada nome de lista contenha `ABC`, de modo que todas as seis listas correspondam à consulta filtrada.
1. Execute a seguinte consulta do GraphQL com `pageSize` definido como dois e `currentPage` definido como um:

   ```graphql
   query {
     customer {
       requisition_lists(
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```

1. Execute esta consulta do GraphQL:

   ```graphql
   query {
     customer {
       requisition_lists(
         filter: { name: { match: "%ABC%" } }
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```


<u>Resultados esperados</u>:

* A consulta `requisition_lists` retorna `total_count` igual ao número total de listas de requisições pertencentes ao cliente, independentemente de `pageSize` e `currentPage`.
* Os dados de paginação permanecem consistentes com o conjunto de resultados correspondente completo.

<u>Resultados reais</u>:

`total_count` retorna somente o número de itens na página atual, como dois em vez de seis.
